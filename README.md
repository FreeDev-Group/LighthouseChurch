## Project Overview

This repository contains the documentation, project management resources, quality assurance materials, and custom development resources for the **LightHouse Church website project**.

The project is being developed by **FreeDEV** as part of its practical web development and digital project experience program.

The website will provide LightHouse Church with a modern, accessible, responsive, and maintainable online presence that communicates the church's identity, activities, ministries, resources, and contact information.

The project also has an **educational objective**: FreeDEV mentees will participate in the project to gain practical experience with WordPress, web development, project collaboration, quality assurance, and professional development workflows.

---

## Project Objectives

The main objectives of this project are to:

* Build a professional website for LightHouse Church.
* Present the church's identity, vision, activities, and ministries online.
* Provide visitors with relevant information about the church.
* Publish sermons, resources, news, and events where applicable.
* Provide clear contact and communication channels.
* Ensure the website works well on desktop, tablet, and mobile devices.
* Apply basic web accessibility principles.
* Apply appropriate SEO practices.
* Follow basic security and performance best practices.
* Create a maintainable WordPress website.
* Give FreeDEV mentees practical experience working on a real-world project.

## Development Approach

The project will follow a shared development workflow rather than having each team member maintain a separate WordPress database.

### Planned workflow

```text
Requirements
     ↓
Planning
     ↓
WordPress DEV
     ↓
Development
     ↓
Internal Review
     ↓
QA Testing
     ↓
STAGING
     ↓
Stakeholder Review
     ↓
Corrections
     ↓
Final QA
     ↓
PRODUCTION
```

### Environments

#### DEV

The shared development environment where FreeDEV team members will work on the website.

Purpose:

* Website development
* Content integration
* Design implementation
* Feature development
* Internal experimentation

#### STAGING

A near-final copy of the website used for:

* QA testing
* Final review
* Stakeholder review
* Final corrections

#### PRODUCTION

The official public website used by LightHouse Church visitors.

Direct development work should not normally be performed on the production environment.

## Team Workflow

The project will use GitHub to manage tasks, documentation, issues, and technical resources.

### Task workflow

```text
BACKLOG
   ↓
TO DO
   ↓
IN PROGRESS
   ↓
REVIEW
   ↓
QA
   ↓
DONE
```

Each task should have:

* A clear title
* A description
* An assigned team member
* Requirements
* Acceptance criteria
* A defined deliverable

### Example

**Task:** Create About Us page

**Requirements:**

* Church introduction
* Mission
* Vision
* History
* Leadership information, if approved

**Acceptance Criteria:**

* Content has been provided or approved.
* Page is responsive.
* Images have appropriate alternative text.
* Links work correctly.
* Layout is consistent with the website.
* No visible functional issues remain.

## Quality Assurance

Before deployment, the website will undergo several categories of testing.

### Functional Testing

Testing will verify:

* Navigation
* Links
* Forms
* Buttons
* Menus
* Search functionality, where applicable
* Events
* Sermons/resources
* Media
* Other implemented features

### Responsive Testing

The website will be tested on:

* Desktop
* Tablet
* Mobile

### Browser Testing

Where applicable, testing will cover major modern browsers such as:

* Google Chrome
* Mozilla Firefox
* Microsoft Edge
* Safari

### Accessibility Testing

The team will verify basic accessibility considerations, including:

* Alternative text for meaningful images
* Heading structure
* Keyboard navigation
* Color contrast
* Form labels
* Link clarity
* Accessible navigation
* Responsive text and layout

### Performance Testing

The team will review:

* Image optimization
* Page loading
* Unnecessary plugins
* Large media files
* Basic performance issues

## Project Principles

The team will follow these principles throughout the project:

1. **Build collaboratively**
2. **Document important decisions**
3. **Keep tasks clear and manageable**
4. **Test before considering work complete**
5. **Do not make unapproved public changes**
6. **Protect the production environment**
7. **Keep stakeholder requirements visible**
8. **Use the project as a real-world learning opportunity**
9. **Prefer simple and maintainable solutions**
10. **Focus on delivering a functional, accessible, and sustainable website**
