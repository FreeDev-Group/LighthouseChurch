# LightHouse Church: Website Navigation

## 1. Purpose

This document defines how users will navigate through the approved LightHouse Church website structure.

The navigation is designed according to standard web usability and accessibility practices while keeping the website simple, clear, consistent, and easy to use on desktop and mobile devices.

The approved website structure is documented in:

`docs/LightHouse-Church-Website-Project-Requirements.pdf`

This document does not introduce new pages or modify the approved website structure.

---

## 2. Primary Navigation

The primary navigation should provide direct access to the main sections of the website.

### Primary Menu

- Home
- About Us
- Ministries
- Events
- Sermons / Resources
- News / Articles
- Gallery
- Giving / Support
- Contact

---

## 3. Navigation Principles

The navigation will follow these principles:

- Use clear and descriptive labels.
- Keep the primary navigation simple and easy to scan.
- Avoid unnecessary menu items.
- Avoid excessive levels of nested menus.
- Use consistent navigation throughout the website.
- Ensure every navigation item leads to a meaningful destination.
- Avoid duplicate links where they do not provide additional value.
- Keep important and frequently accessed sections easy to find.
- Maintain the same navigation logic across desktop and mobile.
- Ensure navigation can be operated using a keyboard.
- Ensure navigation elements have sufficient visual distinction and accessible focus states.

---

## 4. Dropdown Navigation

Dropdown menus should only be used when a section contains multiple related pages or categories that require grouping.

Dropdown menus should:

- Have clear parent labels.
- Contain logically related items.
- Avoid excessive nesting.
- Remain usable on mobile devices.
- Be accessible using keyboard navigation.
- Provide a clear way for users to access the parent section when appropriate.

The exact dropdown structure should be confirmed during WordPress implementation based on the final approved content.

---

## 5. Footer Navigation

The footer should provide access to useful secondary links without duplicating the entire primary navigation unnecessarily.

The footer may include:

- Important website pages
- Contact information
- Social media links
- Giving / Support
- Privacy Policy
- Other applicable legal or informational pages

Only confirmed and approved information should be published.

---

## 6. Mobile Navigation

The navigation must be fully responsive.

On smaller screens:

- The primary navigation should be accessible through an appropriate mobile menu.
- Menu controls should be clearly identifiable.
- Navigation items should be easy to tap.
- Dropdowns or expandable sections should remain usable.
- Users should be able to open and close the menu easily.
- Keyboard and assistive-technology accessibility should be considered where applicable.
- The navigation should not obstruct important page content unnecessarily.

---

## 7. Navigation Consistency

The same navigation system should be maintained across the website.

Users should be able to:

- Identify where they are on the website.
- Return to the homepage easily.
- Access the main sections without having to return to the homepage.
- Understand the purpose of each navigation link.
- Navigate between related pages logically.

The website logo should normally provide a link back to the homepage.

---

## 8. Calls to Action

Important actions should be easy to discover without overcrowding the navigation.

Potential calls to action may include:

- Giving / Support
- Contact
- Events
- Sermons / Resources

The final placement and visual treatment of these actions should be determined during the design and WordPress implementation phases.

---

## 9. Accessibility Considerations

The navigation should follow applicable WCAG principles.

Key considerations include:

- Keyboard accessibility
- Visible keyboard focus
- Meaningful link names
- Sufficient color contrast
- Logical focus order
- Proper semantic navigation structure
- Accessible mobile menu controls
- Avoiding navigation that depends exclusively on hover
- Compatibility with screen readers and assistive technologies

Accessibility testing will be performed during the QA phase.

---

## 10. Implementation in WordPress

The navigation structure will be implemented using WordPress navigation/menu functionality provided by the selected theme or appropriate WordPress components.

The implementation should maintain:

- Consistent menu structure
- Responsive behavior
- Accessibility
- Clear labeling
- Easy content management
- Minimal unnecessary customization

Any custom navigation code should be documented and maintained through the project repository where applicable.

---

## 11. Navigation Validation

Before the navigation is considered complete, the team should verify:

- [ ] All primary navigation items are present.
- [ ] All links lead to the correct destinations.
- [ ] No unnecessary or duplicate menu items are present.
- [ ] Dropdowns work correctly where used.
- [ ] Mobile navigation works correctly.
- [ ] Keyboard navigation works correctly.
- [ ] Focus states are visible.
- [ ] Navigation labels are clear and consistent.
- [ ] Footer navigation works correctly.
- [ ] Navigation is consistent across major pages.
- [ ] No broken navigation links are present.

---

## 12. Approval and Scope

The website's overall page structure has already been reviewed and confirmed by LightHouse Church.

This document defines the navigation approach for implementing that approved structure.

Any change that introduces new pages, removes approved pages, or significantly changes the information architecture should be documented and reviewed before implementation.
